    HOW THE SYSTEM WORKS

    1. Login: the student taps their RFID card on the MFRC522 reader. The ESP32 sends the card UID to the server, which checks it against the registered cards and the prepaid balance.
    2. Supply: if the card is valid and the balance is above ₹0, the server sets the relay ON and the ESP32 switches it on its next sync. Tapping the same card again ends the session.
    3. Metering: every sync the ESP32 sends the PZEM-004T readings (voltage, current, power, energy). The server bills the new energy (Wh) at the set tariff and deducts it from the student's balance.
    4. Protection: the supply is cut automatically when the balance runs out or the voltage leaves the safe range. Current flowing while the relay is OFF raises a theft alert.
    5. Remote control: Power ON/OFF and recharges on this dashboard update the database, and the ESP32 picks them up within one sync interval.

    DEVICE ENDPOINT

    The ESP32 talks only to POST /api/device/sync (Python / Flask, app.py) with header X-Device-Key. Pin wiring and setup steps are in README.md.

    TROUBLESHOOTING

    • IoT Node shows Offline: check the ESP32 Wi-Fi details and the server IP in the firmware, and allow port 5000 through Windows Firewall.
    • Fault = SENSOR: the PZEM-004T is not answering. It needs 230 V AC on its input terminals to respond, and TX/RX must be crossed.
    • Power ON refused: a student must be logged in with a card and have a balance above ₹0.
